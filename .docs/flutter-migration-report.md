## 2. Native-config versioning fix (reproducibility)

**Problem.** The repo root `.gitignore` had a legacy Expo/RN "# Native" block with
bare `android/` and `ios/` patterns. Because those patterns match a directory of
that name *anywhere* in the tree, they silently excluded the **Flutter** native
projects under `apps/flutter/` — `git ls-files apps/flutter/android` returned **0
files**. Two required Android overrides therefore lived only in an untracked,
gitignored folder and would be **lost on a fresh checkout**:

- **`compileSdk = 36`** — `apps/flutter/android/app/build.gradle.kts`. `file_picker`
  (S1 upload) pulls a `flutter_plugin_android_lifecycle` whose AAR metadata
  requires compileSdk 36; without it the Android build fails the AAR check.
- **`RECORD_AUDIO` permission** — `apps/flutter/android/app/src/main/AndroidManifest.xml`.
  Required for the F3 recording modal's mic capture.

**Fix (chosen approach: version the native projects).** The root `.gitignore`
"# Native" rules were **scoped to the legacy RN app only** — `android/`/`ios/`
became `apps/mobile/android/`/`apps/mobile/ios/`. The `apps/flutter/<platform>/`
native projects now version in full, while `apps/mobile`'s native folders stay
ignored. Each `apps/flutter/<platform>/.gitignore` (generated by `flutter create`)
still excludes that platform's build artifacts (`build/`, `ephemeral/`, `.gradle/`,
`Pods/`, `xcuserdata`, `local.properties`, keystores…), so no build output is
committed.

- **Where it lives:** root `/.gitignore` "# Native" block (the negation/scoping),
  plus the now-tracked override files themselves (build.gradle.kts, AndroidManifest.xml,
  Info.plist, entitlements).
- **Why this over a post-create script:** a generator/setup script would re-run
  `flutter create` and **re-overwrite** the hand-edited overrides every time;
  versioning the actual files makes a fresh checkout buildable with **zero** extra
  setup steps. `compileSdk 36` and `RECORD_AUDIO` are now part of the tree.
- **Verification:** after the fix, `git check-ignore` no longer ignores the override
  files; `git ls-files -o --exclude-standard apps/flutter/{android,ios,macos,windows}`
  lists **105** source files and **no** build artifacts; `apps/mobile/android|ios`
  remain ignored.

Setup for a fresh checkout is documented in `apps/flutter/README.md`.

## 7. Recommendation — when/how to retire the RN mobile app

Do **not** retire `apps/mobile` yet. Retire it once **all** of the following hold
(criteria, not the act):

1. **iOS + macOS build pass on a Mac** (Xcode + CocoaPods + signing) and **Windows
   build pass** on a Windows host — each producing a runnable artifact. These are the
   only platforms still build-unverified.
2. **Manual emulator/device recording pass**: one real-device (or pixel7 AVD) run of
   the recording modal → upload → Core processing → detail, on Android and iOS.
3. **Smart-spaces parity decided**: either port the rail or formally accept dropping
   it (it is currently a no-op placeholder, so accepting is reasonable).
4. **CI green** on `flutter analyze` + `flutter test --concurrency=1` + the three
   buildable targets, wired into the pipeline.
5. **Store/release path ready**: signing identities, store listings, and an update
   strategy to replace the dropped expo-updates OTA (store updates or
   `shorebird`/codepush-style if OTA is required).

**How:** ship Flutter to the same audience on web + Android first (both verified),
keep RN installed in parallel for one release cycle as a rollback, complete the
iOS/macOS/Windows build passes, then flip stores to the Flutter build and freeze
`apps/mobile`. Delete `apps/mobile` only after one stable cycle on Flutter in
production.
